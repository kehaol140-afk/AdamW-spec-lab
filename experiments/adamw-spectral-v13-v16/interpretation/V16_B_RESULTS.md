## 2. 三个冻结问题的回答

1. **低 β1 历史记忆不能解释 F/P 收益**：S5(0.5)/S6(0)/S7(全 0.5) 全部 ≥ 最佳普通 S（+0.004~+0.030），无一接近 F1(−0.122)/P1(−0.153)。β1 降到底（S6：m≡g，cos_g_m=1.0）仍无增益 → **剩余收益不是"动量不匹配"问题**。
2. **LR 边界**：三族最优 LR 均为 0.001（下边界），冻结 S8/F4/P4 外扩至 0.0003 后全部大幅变差（+0.38~+0.42）→ **0.001 不是真边界，向下已解析**（0.0003 差、0.006/0.003 差 → 最优在 0.001–0.003 之间，已受网格分辨率限制但方向收益本身在全部三个 LR 上同号：每个 LR 上 P1/F1 均排该 LR 组第一）。
3. **A1 角点配方 (a=8,b=2) 不从头迁移**（S4 比普通 S 差 +0.100）：b 效应是续训场景特有；从头场景获胜配方是 **仅目标块放大**（a=8, b=1）——方向收益跨场景稳健，幅度收益不跨场景。

## 3. route_b 结果与 screen 阶段实现层混淆（重要披露）

- 路由输出：label **F_OR_P_SUSTAINED**；recipes = [b_S1_plain_lr0.001, b_F1_a8_lr0.001] → 进入 C。
- **混淆**：weights-only checkpoint 上限（12）按队列顺序删除了早期 endpoint（S1–S3、F1–F3，deletions.jsonl 有记录）；b_select 只对 endpoint 在位的分支做 screen 评估 → screen 集仅含 {P1: 4.1261, P2: 4.3274}；route_b 的 `screen.get(best_s_id, 0)` 默认 0 语义与"cid 在 screen 中才比较"结合后产生不对称：**F1（无 screen 值 → gain=None → 旁路通过）入选；P1（有 screen 值 → 与缺席基线的默认 0 比较 → gain=−4.126 → 被拒）**。即 dev 第 1 名 P1 被 checkpoint 清理顺序 × 默认值语义排除出 C，而非被真实 screen 数字击败（S1 的真实 screen 值未知；dev H2048 排序 P1>F1 且 screen 内部 P1<P2 与 dev 一致）。
- 后果与处理：C 以 F1 承载 F/P-vs-S 问题（A1/A2 已证 F≈P，差距 9e-5）；P1 的跨 seed 覆盖为**协议执行层缺口**，本报告如实记录，未修改任何冻结代码/队列/阈值。若需补 P1 的 C 验证须用户单独授权。
