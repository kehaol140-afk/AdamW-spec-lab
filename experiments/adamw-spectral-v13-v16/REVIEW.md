# AdamW 谱分配本地首轮：独立复核与下一轮建议

## 结论

原协议的 STOP 应当保留：既没有充分解决 baseline LR 范围，也没有在冻结主 cell 的独立确认文档上发现谱候选超过标量控制的收益。不能把它写成“证明 AdamW 谱改进无用”，也不能把现有结果改判为 PASS。

本轮已经解决小模型实验可运行性，并揭示三项可继续调查的现象：四个选择 cell 都偏好目标块 s=0；M 与真实 A 的几何差异强烈依赖模块；按真实输入衡量的谱影响与 Frobenius 谱能量不同。下一轮应复用 checkpoint 做零新增预训练的反事实诊断，不立即扩 LR/rho/rank 网格。

## 复核范围和限制

阅读了两个上传 ZIP 的源码及差异、配置、报告、CSV/JSON 与日志。独立重算 token 加权 NLL、文档级配对 bootstrap、方向信号、功能能量和日志计数。隔离副本中重跑 CPU 测试：21 个测试，20 通过、1 个因缺少本地 MiniMind 绑定而跳过。未在这里重跑 GPU、未加载用户 checkpoint；轻量包不包含 checkpoint、原始语料、缓存 token 和完整外部 MiniMind 仓库。

所有计算见 evidence/reanalysis.json、cell_reanalysis.csv、grid_token_weighted_aggregate.csv；实际代码行号见 evidence/SOURCE_EXCERPTS.md。

## 1. 工程工作成立，但有边界

Codex 的低内存 smoke 和恢复重放成功。OpenCode 又修复评估及方向诊断中漏掉的输入切片；两个最终源文件仅相应 forward 调用发生改变，另补 CPU 测试。最终两版 active config 内容相同。三条 baseline 真实完成，确认 seed 未启动。资源不再是当前阻碍。

原始资源日志共 5671 条；discover PID 41096 共 5552 条，扣除两条 admission 正好 5550 条。报告所说的 5550 对应此运行子集，不是整个文件行数。最低可用 RAM 1.61155 GiB，最高 RSS 1.64183 GiB，峰值 CUDA reserved 0.3671875 GiB。

注意：固定输入的重复前向 epsilon_null=0，不等于总体数值误差为零。不同目标 cell 重构的普通 AdamW 总 NLL 相差约 1e-8–6e-8；这是当前阈值以下的小差异，不是推翻实验的理由，但下一轮应加入完整重构重复和定向有限差分校验。

## 2. 原始门槛结果可复算

LR=0.0003/0.001/0.003 的终点 lr_select NLL 为 6.572523/5.808333/5.627559。最大 LR 胜出意味着扫描范围未解决，不意味着进一步增大一定更好。

主 cell：seed3407，step256，model.layers.1.mlp.down_proj.weight。

- 选择文档上的 s=0 NLL = 6.213549184632791。
- rho=0.5,s=0.25 NLL = 6.213562171465669。
- 普通 AdamW s=1 NLL = 6.213630957305778。
- 确认文档上的 L(s=0)-L(spectral) = -2.118408343e-6。
- 原方案 bootstrap 区间复算为 [-9.48427599e-6, 5.69879990e-6]。

后验增加的比较：确认集 L(AdamW)-L(s=0)=3.3482100e-5，bootstrap 95% 区间 [-7.54247034e-6,7.20389685e-5]，仍包含零。不能声称“冻结目标块已经得到可靠收益”。这个比较是此次复核新增的描述性计算，不改变原主判据。

“差距小于 1e-4，所以实质并列”不是充分的统计论证；应使用对应配对差值、区间和冻结阈值。也不能仅因没有显著差异就声称严格等效。

## 3. s=0 是四个 cell 的共同现象，不只主 cell

按 token 加权重新聚合，两次梯度构造合并：

| checkpoint/模块 | L(s=1)-L(s=0) | 最佳谱候选相对 s=0 的损失增加 |
|---|---:|---:|
| step128 FFN | 9.85756823e-5 | 1.70219217e-5 |
| step128 attention | 3.54874823e-5 | 3.50851567e-6 |
| step256 FFN | 8.17726730e-5 | 1.29868329e-5 |
| step256 attention | 1.26661557e-4 | 2.47311897e-5 |

这些是同一 16 个 probe_select 文档上的探索性描述，不是四次独立训练验证。原报告“32 个 probe_select 文档×replicate”的表述应改为“16 个不同文档，每个有 2 次梯度构造，共 32 条文档-构造记录”。

## 4. 主 cell 的响应可以用一阶项定量解释

应按 token 加权计算方向信号，不能用每文档 NLL 梯度的无权平均解释 token 加权总 NLL。

主 cell 在当前条件基点上：

q_H = -0.03254917714，q_R = -0.01286697256，eta = 0.001782323139。

对于 D=s(rho H+R)，局部一阶预测为 ΔL≈-eta*s*(rho*q_H+q_R)。

- 普通 AdamW 的一阶预测损失增加 8.09462545e-5，实际为 8.17726730e-5。
- rho=0.5,s=0.25 的预测增加 1.29849197e-5，实际为 1.29868329e-5。

因此，此处不必假设“大方向原本有可靠下降信号，却被二阶曲率步长限制”才能解释观察；在这批文档和这个条件基点上，两组方向的加权一阶信号已经都是负的。对当前两组聚合方向、非负 rho/s，在足够小步长范围内做正系数重分配不能把这两个负信号组合成正的下降信号。这不是对所有奇异方向、所有数据或其他状态的结论。

## 5. 当前测量是条件边际效应，不是原 checkpoint 上的独立块更新

pilot_workflow.py::_next_build 会先对全模型 opt.step；然后 probe 只把目标块设为 decay-only 的 base，再替换目标候选。因此 s=0 对照中其他参数已经走了一步普通 AdamW。

原实验确实按照协议执行，这不是实现错误。但 s=0 胜出只说明：在其他参数已经完成该次普通更新的条件下，加入目标块该方向没有提高这个局部验证指标。它不证明该块在原始 checkpoint 上独立更新无用。

建议以共同衰减后的状态为基准，构造四个数据更新开关：F00（都关）、F10（只开目标块）、F01（只开其他参数）、F11（全开）。同一份梯度/moments 生成所有反事实，不在各状态重新计算更新。目标块收益分别是 F00-F10 和 F01-F11；交互项是 F11-F10-F01+F00。

## 6. 发现需要本地核实的评估目标缺口

prepare_data.py:191 的实际表达式为：

    ids = [bos] + tokenize(text)[:seq - 1] + [eos]

训练使用完整文档加真实 EOS 后拼接；评估若文档内容超过 255 token，就把内容截断，然后强行添加 EOS。这样最后一个评估标签不是原文中的真实续接 token，而是人为 EOS。

只有原文内容大于 255 token 才属于这一问题。现有 CSV 中，长度达到上限的文档为 lr_select 8、probe_select 5、probe_confirm 17，总计 30；但没有原文/token 缓存，不能在这里把这 30 个全部判成截断。需要读取本地原文恢复真实长度。

这不是此次 257→256 forward 切片造成的。切片修复的是模型输入长度，保留了旧评估标签。旧结果仍是对旧标签定义的真实测量；不能在未重评估前声称人工 EOS 就是负结果根因。

对长期自回归预训练更忠实的自然前缀可表示为：([bos]+完整内容+[真实eos])[:seq+1]。短文真实 EOS 保留，长文截断处不捏造 EOS。另需单独区分“独立文档前缀评估”与“自然拼接窗口评估”的上下文差异；这两种口径的绝对 NLL 不能直接当作同一指标比较。

补充后验观察：主确认集长度达到上限的 17 文档上，L(AdamW)-L(s=0)约 -1.14e-5；其余 47 文档约 +5.83e-5。没有做预注册分层确认，不能由此归因 EOS；反而说明不能简单认定长文人工 EOS 必然解释 s=0。

## 7. 已有两项比“继续扫比例”更具体的研究线索

| checkpoint/模块 | A 首奇异分量的 Frobenius 能量占比 | 真实输入上的模块输出能量占比 | M 奇异基对角捕获 A 能量 |
|---|---:|---:|---:|
| step128 FFN | 32.51% | 51.40% | 49.88% |
| step128 attention | 74.66% | 98.03% | 89.18% |
| step256 FFN | 17.29% | 26.11% | 51.73% |
| step256 attention | 51.18% | 86.74% | 86.66% |

前两列不是同一个量。对 A=UΣVᵀ、实际输入二阶矩 Cx，第 i 个奇异分量的输出能量是 sigma_i²*v_iᵀCx*v_i。attention 的更新作用在实际输入上比原始 Frobenius 谱更加集中，这支持继续考察输入激活加权的谱影响，而不支持直接把头部删除。

M 的 paired capture 是 A 在 rank-one 配对基 span{u_i v_iᵀ}上的能量比例；剩余能量不全等于“坏方向”“丢失信号”或“非对角耦合”。FFN 和 attention 的不同只能说明预条件对更新几何的改变具有模块差异，须进一步与真实下降信号建立联系。

attention/step128 的剩余部分 q_R≈+0.002513、头部 q_H≈-0.015317，提示 rho<约0.164 时一阶趋势可能改变，而旧网格最小 rho=0.5。但是剩余部分文档 bootstrap 区间约[-0.00390,0.01130]跨零；这是后验辅助线索，不应据此立即扩 rank/rho 寻找赢家。

## 8. 次要的审计/成本修正

1. head gap 非零只能排除该次分解中的近简并标志，不能单凭它宣布跨 batch 奇异向量稳定。
2. svd_seconds 的计时从 SVD 前开始，到构造全部候选列表之后结束，当前不是纯 SVD 时间。不要直接用于推断部署开销。
3. runtime.csv 有正式训练1536步、smoke/replay24步。另有5个完整 probe_cell×2rep，各调用一次 opt.step，合计10次隔离虚拟更新；不推进正式轨迹，但应计入真实计算账目。按源码和成功记录推断合计1570次GPU optimizer调用，而不是把probe写成0成本。
4. run.py::report 仍硬编码 IMPLEMENTED_NOT_FORMALLY_RUN。原 gate 文件正确，但此生成器以后可能覆盖手写报告并误写状态，应修为读取真实 manifest/日志。该报告工具问题不改变已有数值结果。

## 推荐下一步

新建独立只读复核子协议，不覆盖原 STOP。复用旧 checkpoint，先核验评估标签，然后做四状态反事实与 M/A/当前梯度的独立下降信号对比。新增正式预训练步数为0，不重跑三条baseline，不自动加LR/rho/rank或seed，不使用在线确认数据调候选。具体任务见 PROMPT_CODEX.md、PROMPT_OPENCODE.md。
