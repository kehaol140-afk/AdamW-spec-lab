## 2. 修好比较方法，定位重复构建差异

### 2.1 证据身份与浮点复现分开

文件、checkpoint、数据、代码与配置的身份核验继续使用严格哈希，不取消父校验。子实验通过明确的 parent-dependency manifest 读取旧 checkpoint；新源码有自己的哈希，不伪造旧哈希，也不要求旧 checkpoint 含有未来子源码的哈希。

所有张量摘要使用同一规范：稳定的逻辑参数名排序、名称长度与字段边界、dtype、shape、固定连续布局和字节表示；区分 None、缺失项和零张量。优化器状态须稳定映射到逻辑参数名，不只依赖进程中的参数 ID。包含共享参数别名及 optimizer group 配置；不通过转换精度来获得相同摘要。

先用 CPU 测试证明：同名同值张量在不同字典插入顺序下摘要一致；同 shape 的真实数值变化、dtype/shape 变化、None 与 zero 变化可以被检出。

重复计算同时逐张量输出：`max_abs`、relative L2（注明分母和零范数处理）、方向余弦、不同元素数、最大差异索引和数值、非有限值；比较原始梯度、token 归一化后梯度、全局 clip 后梯度、m/v/step、真实 A、实际更新增量与更新后参数。报告最先出现差异的阶段，不能只报一个总 SHA。

### 2.2 先排查状态，再考虑数值后端

同一 checkpoint/同一构造窗口，在相同逻辑状态下检查：
- RNG（Python/NumPy/CPU/CUDA）、所有子模块 train/eval 状态、参数及持久/非持久 buffer。
- m/v/step、param groups、学习率位置、weight decay、grad/None、global clipping、AMP 状态、数据 cursor、token IDs/mask/count。
- tied 参数、optimizer 重复注册、浅拷贝/别名导致的快照污染、梯度累积残留、模型 cache。
- 诊断函数、日志或状态加载本身是否改变了待比较状态。

一次只改变一个已定位因素。先保留父 BF16 生成路径，定位具体差异；必要时再在独立、可记录的模式下采用确定性控制或 FP32 参考。环境/内核原因未被定位就写 `NOT_IDENTIFIED`，不能笼统归因“GPU 天生不稳定”。

FP32 或不同 attention 后端可以用于参考验收，但它改变了梯度生成条件；必须分别报告生成精度、生成后端、评估精度、评估后端。优先尝试对冻结的父 BF16 更新使用更稳定的评估路径，不把 FP32 重新生成的方向当成同一实际 BF16 更新。

本轮不要求无休止的内核溯源。若表示/恢复问题排除后只剩可量化数值波动，进入下面的效应误差验收；若仍有状态污染或来源错误，不得靠容差放过。

## 3. 数值验收要验证我们最终读取的量

保留已有正确的 AdamW 公式一致性、共享参数语义、完整恢复等测试。对同一个实际构建，将原参数、decay-only 基点、真实 delta、A、m/v、构造梯度与窗口 ID 冻结到子目录；后面的反事实全部复用该构建，不能每个候选重新构建方向。

把“同一份已冻结更新的反复评估”与“同一输入重新生成更新后再评估”分成两个重复性检查。单次 forward 的 epsilon_null=0 不代表全部测量误差为0。

需要验收的损失差（nats/token）是 `I_before`、`I_after` 和 interaction。不得把每参数误差 `8e-6` 直接与损失阈值 `1e-5 nats/token` 比较。

新的工程分辨率目标预先定为：这些读数的观测数值差异包络不超过 `2e-6 nats/token`，即原 `1e-5` 实用判据的20%。这是本轮工程设计值，不是数学误差上界或新科学显著性门槛，不回改旧判据。
- 使用主 FFN、固定窗口0、旧 probe_select 中按 doc_id 排序的前8个文档及其 legacy/natural 配对版本作数值校准；该小集合不用于挑选谱赢家。
- 同一冻结构建重复评估至少2次；同输入在进程内重复构建至少2次，另有一次新进程规范对比。保存分阶段数值差异和效应差异。
- 先在校准集合确定允许的测量模式，再看本轮研究读数，不能按更有利的损失选择精度/后端。
- 全量汇总中应至少对主 FFN、窗口0的实际评估集合复核两份重复构建/重复读数，避免仅凭8文档校准宣称128文档都已验证。
- 不把少量重复的最大差异称为严格上界；效应小于数值包络、统计区间跨零或不同模式符号冲突时，明确写 `NUMERICALLY_UNRESOLVED`，不硬判正负。

对与最终评估完全相同的 token 权重、目标、基点和更新方向做自动微分/双侧有限差分。检查方向正负号，使用预先固定的少量扰动尺度（例如对 Frobenius 单位方向使用 `h=0.003,0.001,0.0003`），并检查真正施加的扰动。记录舍入、差分损失量级和尺度敏感性，不能只保留最容易通过的一档或通过增加容差掩盖失败。近零导数不稳定时标记分辨率限制，不要求它制造一个非零信号；必要时以 CPU FP64 小型确定性测试验证导数实现，而非把整个真实模型转为 FP64。

只有科学无关的表示差异，或在上述读数尺度上足够小且已说明的浮点波动，才允许用新的数值判据替代子实验的“全部张量重复计算必须同 SHA”。修改理由、比较对象、阈值和测试写入审计，不删除来源校验。

## 4. 完成最小但真实的四状态与方向诊断

### 固定对象

沿用 V12 manifest：seed3407、peak LR=0.003、step256，原来预先定义的4个不重叠构造窗口；不得按结果重新挑窗口。主目标 `model.layers.1.mlp.down_proj.weight`，辅助目标 `model.layers.1.self_attn.o_proj.weight`。不加层、不扫rank、不扫rho。

每个窗口都从同一个真实 step256 状态恢复，用原本有效 batch、clip、bias correction、eta和各组衰减构建实际下一步。不同窗口只代表构造批次变化，不是独立训练 seed。一次全模型构建复用于两个目标，不为每个目标重复 step。

### 四状态定义

对真正参与更新的唯一参数，先形成一次相同 decoupled decay 后的共同基点 `base`。None-gradient 参数沿用父优化器不更新/不衰减的实际语义；不得把整模型无条件衰减一次。令 `delta=actual_updated-base`，构造：
- F00：base；
- F10：base + 目标块的 delta；
- F01：base + 其余参数的 delta；
- F11：base + 全部 delta。

顺序评估，避免同时保留四个完整 GPU 模型。验证 F11 与该次真实 AdamW 更新一致，F01 与同构建下原条件 s=0 一致；对 rho=s=1 的A公式重构单独报告舍入误差。不能要求与旧历史 CSV 逐位一致来替代“同一构建下”的数学恒等式。

逐文档保留 loss_sum/count，统一以 `sum(loss_sum)/sum(count)` 汇总。定义：
`I_before = F00-F10`，`I_after = F01-F11`，`interaction = F11-F10-F01+F00 = I_before-I_after`。

### 评估视图

1. 对旧 probe_select/probe_confirm 文档使用配对 legacy 与 natural-prefix 视图，直接检查标签改变是否改变主位置开/关更新效应。旧 probe_confirm 此后只作为已使用的探索材料，不能再称全新独立确认集。不要混入 lr_select 文档做新的效果选择。
2. 复用 V12 已冻结的128个新 probe_select 文档的自然前缀视图，不另挑文档。所有这些都是探索诊断，保留未来 final_holdout 不接触。
3. 既有 packed 视图只做描述性检查，无需为它扩大样本；同来源文档、重叠窗口或连接成一个簇时，不伪造独立文档置信区间。不同视图绝对 NLL 不当作相同目标。
4. 构造 batch 上的结果可作训练目标 sanity check，与独立数据上的结果分开标注。

对于可用的自然文档样本，按文档配对重采样后重新计算 token 加权比率；多个窗口在同一文档内聚合或明确分层，不能当作更多独立文档/seed。对于 EOS 因素，计算同一构建、同一文档上 `I_natural-I_legacy` 的配对差，而非仅比较两个NLL水平或分别看两个区间。

先完成主 FFN、窗口0的小型验收；通过后自动完成既定4窗口与两目标，不根据正负结果提前终止。资源/数值/预算约束触发则如实保存部分结果，不写完整通过。

### 必需的方向与实际输入诊断

在F00和F01两个基点，用不写入真实moments的探测梯度，对 `A`、`M_plus`、当前构造梯度，以及A的rank-1头部/剩余部分测量：token加权内积、方向余弦、匹配A范数后的内积。保存逐文档贡献或足够的可复算统计，不只保存一个无不确定性的全局均值。零范数正确处理。用于构造与用于评价的数据来源分开列明。

流式测量真实模块输入上的头部/剩余输出能量、联合能量与交叉项，不保存完整Cx或全模型Hessian。输出基点、输入mask、有效token数和Frobenius能量份额；参数谱与功能变化不混称。SVD只用于选定小矩阵。几何和方向统计是诊断，不等同于某个新优化器的终点收益。

这些测量是研究准备中的探索性证据，不授权任何谱规则搜索或真实持续训练。
