# OpenCode执行任务：有限NS更新的目标价值，R0＋R1

用户已批准继续做有界筛查。请用中文汇报。

先完整阅读 `R0_R1_EXECUTION_PROTOCOL_v1_1_CN.md`、`r0_r1_contract.json` 和 references/ 中的旧理论草案、独立复查。新协议明确修改了旧草案的网格、扩展、检查方案数和预算；原始历史结论不覆盖、不倒签。

## 本轮目标

1. 统一真实LR时钟和实际data-update范数后，局部幅度正信号是否仍存在？
2. O组相对倍率是否提供超过全局倍率的额外收益？
3. 相同a/b、相同O组更新范数下，NS3结构是否提供独立目标价值？在两结构各获同样搜索机会后是否仍成立？

R2、完整预训练收益和强文献基线优越性本轮不回答。不要把局部信号写成新优化器或顶会结果。

## 执行顺序

R0必要修复与测试 → 绑定本轮输入并落盘SHA → R1校准网格 → 根据初始校准结果自动一次扩展 → 锁定全部选择 → 检查侧评价 → 独立重算与中文报告。

R0通过且资产齐全后直接执行R1，不再停在“只生成协议”。无法获得checkpoint/数据、无法统一时钟或实际等范数、达到资源上限，才停止并报告精确阻塞。

## 关键要求

- 复用现有muon_spectral_allocation及seed3101的step512/1536完整状态；不新训父轨迹、不改旧项目。
- load之后实际写回Muon和辅助AdamW的下一步LR；native、候选、WD和计数使用同一时钟。
- 直接原生step作对照；独立恢复buffer/CPU step；A→B→A无污染；参考参数必须在load后取得。
- 历史tie或median来源无法追溯就标UNKNOWN；本轮新规则先落盘，不改选旧赢家，不补造旧时间线。
- 每state8个新完整train batches，4校准、4检查。选择规则、成员排重及评价资源按协议。
- 所有unique参数共同clip；只改变Muon数据更新，辅助AdamW和WD不跟随a/b缩放。
- O组固定为所有层attention output projection，不因结果换组或只保留有利层。

## 交叉实验

初始 a={0.5,0.75,1}，b={0.75,1,1.25}，结构={NS5,NS3_MATCHED}。
NS3_MATCHED每batch用同一实际H计算U3和U5，并以整个O组的norm匹配；不是逐层各归一，也不是免费部署方案。

边界规则按协议第4节：仅依据初始校准的near-best集合，跨状态和结构取触发并集；a可补0.25/1.5，b可补0.5/1.5，只补一轮。两状态、两结构必须补齐同一最终Cartesian网格。不因检查结果扩点。

扩展后仍在边界，标AMPLITUDE_RANGE_UNRESOLVED，不说全局幅度已充分校准。

范数验证要看真正写入参数后的data delta，并与共同WD后的参数比较。禁止只打印计算中的gamma就说已等范数。

## 选择与检查

按协议锁定N、G、A、S_at_A、S、A_at_S、G_at_A以及两个诊断参考；相同方案去重，但保留角色标签。

主比较：
- 全局收益；
- group相对global的选参增量，以及同a只改b的增量；
- 同a/b、等范数的结构增量；
- 同搜索机会下的结构增量；
- NS3最优幅度处的反向匹配结构对照。

每个比较正方向统一为参照NLL减候选NLL。Q固定两域等权，必须分别报告域A/B。
Q_select只用于校准。selection_lock落盘后才访问Q_P1_check。
两目标有历史开发暴露必须说明。Q_P2_endpoint和旧confirm不调用、不挪用。

## 不确定性与成本

native重复一致只说明数值重复性，不代表batch/文档采样误差为0。
报告4个配对差、均值/中位数/SD/符号和探索性配对区间；两checkpoint属于同一父seed，禁止伪装为独立seed推断。
1e-5是本轮局部投入线，1e-6是数值分辨上限和tie容差，不是置信区间或普适科学门槛。

R0 GPU≤15分钟、CPU数值测试≤30分钟。
R0+R1累计≤2 GPU-hours，新输出≤2GiB；包括梯度、NS、评价、编译、重复和失败费用。
逻辑参数点上限：校准416、检查72，共488（R0与重复另外记账）。不要为了凑数量重复完整点，也不得因预算自行砍掉幅度对照。
